# SEO PDCA スキル 設計仕様

> 作成日: 2026-07-25 ／ ステータス: 設計確定（実装計画へ）
> 関連: `docs/superpowers/specs/2026-07-24-content-pipeline-design.md`（記事＋SNS生成）／`docs/seo/`（KW資産）／`docs/owner-todo.md`（GSC/GA4の整備状況）

## 1. 目的

GSC と GA4 から各ページの反応を定期的に解析し、**「計測 → 診断 → 優先度付き改善提案 → （承認して）実装 → 効果検証」** の PDCA を、破綻せず回し続ける仕組みをつくる。単発の分析で終わらせず、**前回提案の結果を検証してから次を出す**ことでループを閉じる。

## 2. スコープ（YAGNI）

- **やること**：C（分析）と、propose-A（優先度付き改善提案）まで。ページ別スコアカード＋ランク付きアクションリスト＋前回提案の結果検証をレポートとして出力する。
- **やらないこと（このスキルの外）**：
  - 改善の**実装**（title/meta改稿・FAQ追加・記事加筆等）は、ユーザーが提案から選び、通常の承認フロー（CLAUDE.md §0）で別途実施する。自動実行では本番を一切触らない。
  - 記事・SNSの**生成**は `content-pipeline-design.md` の担当。本スキルはその入力（狙うべきKW・改稿対象）を供給する。
  - Ahrefs Rank Tracker のプロジェクト登録（CEO対応・未完）。本スキルは `gsc-*` MCP ツールだけで動く前提。

## 3. 発火ペースと仕組み

### 3.1 ペース＝月次（28日）

- SEO は日単位で動かず、新規コンテンツの順位安定に 4〜12 週かかる。GSC データ自体も 2〜3 日の反映遅れがある。日次・週次はノイズを追うだけになる。
- 本サイトはインデックス初期（2026-07-25 に sitemap 投入、登録2ページから拡大中）。深い分析は月次で十分な信号が貯まる。
- link-freshness（月次）と同じリズムに揃え、運用負荷を一定に保つ。
- 将来トラフィックが増えたら隔週へ上げる余地を残す（初期は月次固定）。

### 3.2 発火の仕組み（link-freshness と同方式・半自動）

- 状態ファイル `docs/seo/reports/.last-run`（前回実行日を ISO 日付で記録）。
- **SessionStart フック**（`settings.json` に登録）が起動時に「前回からの経過日数」を判定：
  - 28日以上経過、または未実行なら「【SEO PDCA点検】前回から◯日。`/seo-pdca` で分析を回してください」と表示。
  - 28日未満なら何も出さない。
- ユーザーが Claude Code を開いた際にこの表示を見て、`/seo-pdca` を実行する。**このとき GA4 のログイン済みブラウザが使える同席状態**であることが前提（＝半自動モデル）。

### 3.3 なぜ完全自動 cron にしないか

- GA4 には MCP が無く、取得は「ログイン済みブラウザ操作」か「GA4 Data API の認証セットアップ」のみ。**完全ヘッドレス cron では GA4 に到達できない。**
- Ahrefs（claude.ai MCP 接続）もヘッドレス実行では利用できない場合がある。
- したがって「リマインド → 同席実行」が、GSC＋GA4 の両方を確実に取得できる唯一堅実な形。

## 4. スキル1回の実行フロー（C → propose-A）

### Step 1. GSC データ取得（Ahrefs MCP・自動）

`gsc-*` ツールを使用。取得対象（直近28日 vs 前28日の比較を基本とする）：

- ページ別：クリック / 表示回数 / CTR / 平均掲載順位（`gsc-pages`, `gsc-pages-history`, `gsc-page-history`）
- 主要ページのクエリ（`gsc-keywords`, `gsc-keyword-history`）
- **「あと一歩」クエリ＝平均掲載順位 5〜20 位**（1ページ目に最短で届く勝ち筋。最優先の分析軸）
- インデックス健全性（登録ページ数の推移。sitemap 投入後の吸収状況）

### Step 2. GA4 データ取得（ブラウザ・同席）

`claude-in-chrome` でログイン済み GA4（プロパティ ProofLoop / `G-6DW8LF5H7Q`）を操作。取得対象（前期比）：

- ページ別エンゲージメント（表示回数・エンゲージメント率・平均エンゲージメント時間）
- キーイベント／主要イベント（`gpa_calculate`, `simulator_complete`, `study_abroad_complete`, `affiliate_click`, `simulator_share`）
- 流入元（オーガニック検索の比率、参照元）

> 注：GA4 のブラウザ操作は本セッションで確立済み（realtime／events／custom definitions の操作実績あり）。取得は「探索」またはレポートのスクリーンショット読み取りで行う。

### Step 3. ページ別スコアカード化

GSC（可視性）× GA4（回遊・成果）を突き合わせ、対象ページを4分類にフラグ：

| フラグ | 定義 | 次アクションの方向 |
| --- | --- | --- |
| 伸びてる | クリック or 順位が前期比で改善 | 伸ばす（内部リンク強化・関連KW拡張） |
| 落ちてる | クリック or 順位が前期比で悪化 | 直す（原因診断・改稿） |
| あと一歩 | 主要KWが5〜20位 | 押す（該当KW狙いのH2/FAQ追加） |
| 流入ゼロ | インデックス済みだが表示・流入が僅少 | 診断（インデックス/内容/内部リンク） |

対象ページ：コンテンツ面（`/gpa`・`/guide/*`・`/baito*`）を主対象。団体ページ（2,400+）は個別でなく**集計（合計流入・インデックス率）**で扱う。

### Step 4. 診断と優先度付き提案

フラグ付きページごとに、**根拠つきの具体的改善案**を出し、**インパクト × 手間**でランキングする。

- 例：「`/guide/money` は『大学生 奨学金』で14位。該当KW狙いの H2 と FAQ を追加して1ページ目を狙う（インパクト大・手間中）」
- 例：「`/gpa` は表示回数に対し CTR が SERP 平均より低い → title/meta を改稿（インパクト中・手間小）」

### Step 5. レポート出力

- 出力先：`docs/seo/reports/YYYY-MM-DD-pdca.md`
  - 構成：①前回提案の結果（§5参照）②ページ別スコアカード表（前期比）③ランク付きアクションリスト④データ成熟度メモ
- 索引 `docs/seo/reports/README.md` に1行追記。
- `docs/seo/reports/.last-run` を実行日で更新。

## 5. ループを閉じる仕組み（PDCA の肝）

各レポートの冒頭に **「前回の提案の結果」** セクションを置く。前回レポートのランク付きアクションを読み込み、各項目について：

1. 実装されたか（該当コミット/PR の有無を git 履歴で確認）
2. 実装したなら、対象ページの該当指標が**動いたか**（GSC/GA4 の前期比で検証）
3. 動かなかった提案は原因を考察し、取り下げ or 別アプローチへ差し替え

これにより「回しっぱなし」でなく、**前サイクルの成否を学習してから次を出す**ループになる。

## 6. データ成熟度への適応

- **初期モード（インデックス数が少ない／流入が僅少な間）**：主眼を「インデックス健全性＋ベースライン計測」に置く。順位改善提案は無理に出さず、指標の土台を記録する。
- **成熟モード（流入が貯まってから）**：主眼を「あと一歩KWの押し上げ・CTR改稿・落ちてるページの回復」に置く。
- スキルは実行時にどちらのモードかを判定し、レポートに明記する。

## 8. 依存・前提

- GSC：`gsc-*` Ahrefs MCP ツール（本セッションで利用可能・sitemap 投入済み）。
- GA4：`claude-in-chrome` でのログイン済みブラウザ（半自動モデルで担保）。プロパティは ProofLoop / `G-6DW8LF5H7Q` / `contact@proofloop.jp`。
- 既存資産との接続：入力＝`docs/seo/`（KW資産）、出力の一部＝`content-pipeline-design.md`（改稿・記事生成の対象KWを供給）。

## 9. 成功基準

- 月次で欠かさずレポートが積み上がり、各レポートが前回提案の成否を検証できている。
- 提案が「具体的な改善案＋根拠＋インパクト×手間ランク」の形になっており、ユーザーが即座に実装対象を選べる。
- 実装 → 次サイクルでの効果検証、というループが1周以上回った実績が残る。

## 10. 非目標（明示的に除外）

- 完全自動での本番反映（承認フロー必須）。
- 完全ヘッドレス cron 化（データアクセス制約により不可）。
- Ahrefs Rank Tracker への依存（未登録でも成立させる）。
- 団体ページ個別の逐次分析（集計で扱う）。
