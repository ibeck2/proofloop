# `/clubtasks` タスク詳細・編集モーダルの右サイドパネル化 設計

> 2026-08-19 ブレインストーミングで確定。次は `superpowers:writing-plans` で実装計画に落とす。

オーナーからの追加フィードバック（`docs/superpowers/specs/2026-08-19-clubtasks-gantt-calendar-dates-design.md`が挙げた5点のうち③「タスク詳細の右サイドパネル化」）に対応する。

## 1. 背景・目的

現在`/clubtasks`のタスク編集・新規作成は、画面中央に表示される固定サイズのモーダル（`app/(club)/clubtasks/page.tsx` 1237行目〜、`fixed inset-0 flex items-center justify-center`）。オーナーから「右からヌルっと出るタブのような見た目にしたい」との要望があり、UXの一貫した改善として画面右からスライドインするパネル（ドロワー）形式に変更する。

## 2. 対象範囲

### 対象
- `modalOpen`で制御される1つのモーダル（`page.tsx` 1237〜1509行目）。新規タスク作成・既存タスク編集・アーカイブ履歴の閲覧（読み取り専用）のすべてのケースで同じ器を使う。

### 対象外（現状維持）
- 年度アーカイブ確認モーダル（`archiveModalOpen`）
- アーカイブ取り消し確認モーダル（`unarchiveModalOpen`）

小さな確認ダイアログのため中央表示のままとする。

## 3. アプローチ

新規ライブラリは追加しない。このリポジトリにframer-motion等のアニメーションライブラリは存在せず、単一コンポーネントのためだけに依存を増やすのは過剰（既存の「必要な依存だけを足す」方針に合わせる）。**Tailwind CSSのtransitionユーティリティのみ**で実装する。

### 開閉の2段階制御

現状は`{modalOpen && (...)}`で即座にマウント/アンマウントするため、閉じるときのスライドアウトが作れない。そこで新しいstateを1つ追加し、開閉を分離する：

- `modalOpen`：データ層の開閉フラグ（フォーム初期化・保存処理のトリガーとして現状のまま使う）
- `panelAnimatingIn`（新規）：見た目のトランジション用フラグ。`modalOpen`がtrueになった直後の1tickで`false→true`にし、CSS transitionで`translate-x-full → translate-x-0`を発火させる

閉じる際（`closeModal`呼び出し時）は、
1. まず`panelAnimatingIn`を`false`に戻す（`translate-x-0 → translate-x-full`のtransitionが走る）
2. `setTimeout`でtransition時間（200ms）待ってから、実際に`modalOpen=false`・`editingTask=null`・`form`リセットを行う（＝現在の`closeModal`の中身をここに移す）

このため`closeModal`は非同期的な後始末になるが、フォームstateのリセットは見た目上パネルが隠れた後に起きるため、ユーザーには違和感がない。

### レイアウトの変更点（クラスの差し替えのみ、内部構造は不変）

| 要素 | 現状 | 変更後 |
|---|---|---|
| 外側コンテナ | `fixed inset-0 z-50 flex items-center justify-center p-4 bg-black/50` | `fixed inset-0 z-50 flex justify-end bg-black/50`＋バックドロップの`opacity`を`panelAnimatingIn`に連動 |
| パネル本体 | `w-full max-w-lg rounded-xl ... max-h-[90vh] overflow-y-auto` | `w-full sm:max-w-xl h-full rounded-l-xl ... overflow-y-auto`＋`transition-transform duration-200 ease-out`＋`translate-x-full`/`translate-x-0`を`panelAnimatingIn`で切り替え |
| ヘッダー・フォーム・3セクション（チェックリスト/添付/コメント） | — | **変更なし**。中身はそのまま移植する |

- PC幅：`sm:max-w-xl`（約640px）
- スマホ幅：`w-full`（画面幅いっぱい、実質フルスクリーン）
- 高さ：常に`h-full`（画面縦いっぱい）。中央モーダルの`max-h-[90vh]`は廃止（サイドパネルなので画面いっぱい使う）
- 角丸：右端に張り付くため左側のみ（`rounded-l-xl`、スマホ幅では見た目上ほぼ効かないが害もない）

## 4. 新規に追加する挙動

**Escapeキーで閉じる**（現状未実装）。サイドパネル/ドロワーの一般的な挙動として、`modalOpen`中に`document`へ`keydown`リスナーを追加し、`Escape`で`closeModal()`を呼ぶ。アーカイブ確認・取り消し確認の2モーダルには追加しない（対象外のため）。

## 5. データ・API影響

なし。DB・RPC・APIルートの変更は一切発生しない。`page.tsx`内のJSXとstate管理のみの変更。

## 6. エラーハンドリング

新規に発生しうるエラーケースはない。既存の保存処理（`handleSave`）・読み込み処理は無変更。

唯一の新しい失敗モードは「アニメーション中に高速に開閉操作をした場合の競合」（例：閉じるアニメーション中にもう一度タスクをクリックする）。`setTimeout`のIDを管理し、新しい開閉操作が来たら前のタイマーを`clearTimeout`してから処理することで、状態の不整合（閉じ終わったはずが古いタイマーでリセットされる等）を防ぐ。

## 7. テスト・検証方針

このリポジトリにコンポーネントテスト基盤（RTL）が無いため、`npm test`・`tsc --noEmit`はロジックの型崩れが無いことの確認に留まる。実際の見た目・アニメーション・スマホ幅での挙動は、**`claude-in-chrome`によるブラウザ実機確認が唯一の検証手段**。

確認する項目：
1. 新規タスク作成ボタン → 右からパネルがスライドイン
2. 既存タスクをクリック → 同様にスライドイン、内容が正しく表示される
3. 「キャンセル」「×」ボタン・バックドロップクリック・Escapeキーの4通りで、スライドアウトしてから閉じる
4. 保存ボタンで保存 → パネルが閉じる（既存の`closeModal()`呼び出し経路が保存後も正しく動くこと）
5. アーカイブ履歴閲覧中（読み取り専用）でもパネル化された見た目が崩れない
6. デスクトップ幅（640px程度のパネル）とスマホ幅（375px、フルスクリーン）の両方
7. 年度アーカイブ・取り消し確認の2モーダルが引き続き中央表示のままであること（対象外の回帰が無いこと）

## 8. スコープ外（今回やらないこと）

- フォーカストラップ（キーボードでのTab移動をパネル内に閉じ込める）の追加。現状の中央モーダルにも実装されておらず、今回のスコープでもない
- 未保存の変更がある状態でバックドロップ/Escapeを押した際の確認ダイアログ。既存の中央モーダルも確認なしで閉じる挙動のため、今回もそれを踏襲する
- 他ページ（`/clubfinance`等）の同種モーダルへの横展開。今回は`/clubtasks`のみ
