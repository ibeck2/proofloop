# /clubtasks UI微調整（一貫性・視覚的訴求力の改善） 設計

> 2026-08-19 ブレインストーミングで確定。次は `superpowers:writing-plans` で実装計画に落とす。

## 1. 背景・目的

`docs/superpowers/specs/2026-08-17-clubtasks-overhaul-design.md`で表型・カレンダー・カンバンのスイムレーン化・ガントチャートの4ビューが出揃った。今回はその上に乗る**見た目の一貫性**を直す。オーナー実機確認で次の不自然さが指摘された：

1. ビュー切替ボタン（カンバン／表／カレンダー／ガント）の大きさがラベルの文字数でバラバラ
2. タスク編集モーダルの「種別」入力欄だけ、他の入力欄に比べて縦幅が小さい（＝余白がほぼゼロ）
3. カンバンカードの大きさが、繰り返し・チェックリストの有無で不揃い
4. 文字の書き始め位置までの余白が、場所によってあったり無かったりする
5. 表型ビューがタスク管理を開いたときの最初のビューになっていない（カンバンが先）
6. ProofLoopの6色トークンに固執するあまり、種別（category）で分解したときに競合（Trello/Asana/Linear等）がやっている基礎的な色分けができておらず、視覚的な訴求力に欠ける

今回のスコープは**`app/(club)/clubtasks/`配下の見た目の一貫性向上**に限定する。DBスキーマ変更は行わない。

## 2. スコープ

対象ファイル：
- `app/(club)/clubtasks/page.tsx`（ビュー切替・タスク編集モーダル）
- `app/(club)/clubtasks/TaskCardBody.tsx`（カンバンカードのメタ情報レイアウト）
- `app/(club)/clubtasks/DraggableTaskCard.tsx`（カードのラッパー。変更小さめ）
- `app/(club)/clubtasks/SwimlaneBoard.tsx`（種別グルーピング時の行ヘッダー）
- `app/(club)/clubtasks/TableView.tsx`（種別列にドット追加）
- `app/(club)/clubtasks/GanttView.tsx`（行ラベルの種別表記にドット追加）
- 新規：`lib/tasks/taskCategoryColor.ts`（種別→色の決定的マッピング。純粋関数＋テスト）

**スコープ外**（今回は触らない。理由を明記）：
- `components/ui/Input.tsx` / `Textarea.tsx` 本体のパディング欠如修正。同じ問題が`clubats`など他18ファイルにも存在するが、影響範囲が広く今回のセッションの主眼（clubtasks管理画面）を超えるため、`docs/task-board.md`に別タスクとして記録する
- `CalendarView.tsx`のタスクチップは現状「優先度」で色分けしており、種別色に変えると優先度の情報が失われるため変更しない
- 種別カラーをユーザーが手動で選べる設定UI（Notion/Trello方式）。今回は文字列からの自動決定方式のみ

## 3. 決定事項

### 3.1 ビューの並び順とデフォルト
`表 → カンバン → カレンダー → ガントチャート`の順に並べ替える。`page.tsx`の`view`stateの初期値を`"kanban"`から`"table"`に変更する。

### 3.2 ビュー切替ボタン
4つを均等幅のセグメントコントロールにし、それぞれアイコンを追加する（表＝テーブルアイコン、カンバン＝列アイコン、カレンダー＝カレンダーアイコン、ガント＝ガントチャート系アイコン。実装時にインストール済み`lucide-react`のバージョンで実在するアイコン名を確認する）。現状「文字数の違いがそのまま幅の違いになる」不均一さを解消する。

### 3.3 タスク編集モーダルの入力欄パディング
`page.tsx`内の以下3箇所の`<Input>`に、隣接する`<select>`と揃うclassName（`border border-rule rounded-lg px-3 py-2 text-sm bg-paper text-ink`相当）を追加する：
- タイトル入力（現状classNameなし＝パディング完全ゼロ）
- 種別入力（現状`className="w-full"`のみ）
- アーカイブ名入力（同上）

`Textarea`（詳細説明）は既に`px-3 py-2 rounded-lg`を指定済みのため変更不要。

### 3.4 カンバンカードのメタ情報レイアウト
`TaskCardBody.tsx`で、担当者・レビュー者・チェックリスト進捗・繰り返しの4項目を、現状の「条件付きで縦に積み上がる」構造から、**アイコン+短文のチップを`flex-wrap`で横並びにする**構造へ変更する。
- 情報が0件のタスクは何も表示しない（空行を残さない）
- 情報が多いタスクでも、折り返しにより高さの増分を最小限に抑える
- タイトル・優先度バッジ・期限・種別バッジは現状どおり上部に固定（これらは元々全カードに共通して表示されるため、不揃いの原因ではない）
- `DraggableTaskCard.tsx`側の余白重複（`p-3 pr-4 pt-3`のうち`pt-3`が`p-3`と重複）もあわせて整理する

### 3.5 種別カラー（新しいカテゴリカルパレット）

種別（`task.category`）は固定の列挙値ではなく自由入力（datalist補完）のため、**文字列から決定的に色を算出する**方式を採る。DBスキーマ変更・色選択UIは不要。

- 新規ファイル`lib/tasks/taskCategoryColor.ts`に、`category`文字列を受け取り、あらかじめ用意した固定パレット（中間彩度・Asana/Linear寄り。要素数は実装時に`dataviz`スキルの色選定ロジックで検証しながら決定。8色前後を想定）から**決定的に**1色を選ぶ純粋関数を実装する。同じ文字列は常に同じ色になる（ハッシュ→パレットのインデックスに写像）。`category`が空・未設定の場合は色を返さない（既存の`task.category &&`という条件分岐と整合させる）。
- このパレットは`lib/design/tokens.ts`の6色（ブランドの「印」としての意味を持つ）とは**独立した、種別タグ専用のセット**として新設する。ink・seal等の既存トークンの意味（紺＝面、深紅＝1画面2箇所までの印）は一切変更しない。CLAUDE.md §3の「色を足す前に6色で表現できないか検討する」という原則に対する**意図的かつ限定的な例外**であることを、実装後にCLAUDE.mdまたは`docs/superpowers/specs/2026-07-23-ui-identity-design.md`に追記する。

**適用箇所**：
| 箇所 | 変更内容 |
| --- | --- |
| カンバンの種別バッジ（`TaskCardBody.tsx`） | 現状のニュートラルな枠線→種別色で塗る |
| カンバンの種別ごとスイムレーン見出し（`SwimlaneBoard.tsx`の`rowLabel`表示部） | 色付きドット＋見出しの左ボーダーを追加 |
| 表（Table）ビューの種別列（`TableView.tsx`） | 種別名の前に色付きドット（●）を追加 |
| ガントチャートの行ラベル（`GanttView.tsx`の`（category）`表記） | 同様にドットを追加 |
| カレンダービューのタスクチップ | **変更しない**（現状優先度で色分けしており、種別色に置き換えると優先度情報が失われるため） |

## 4. テスト方針

- `lib/tasks/taskCategoryColor.ts`を純粋関数化し、TDDでカバーする：
  - 同じ文字列を渡すと常に同じ色が返る（決定性）
  - 異なる文字列は（衝突はあり得るが）概ね異なる色に分散する
  - 空文字・null・undefinedは色なし（`null`）を返す
- UIコンポーネント（`TaskCardBody.tsx`・`SwimlaneBoard.tsx`・`TableView.tsx`・`GanttView.tsx`）は表示ロジックのみで、色の決定ロジックは持たない（CLAUDE.md §5の既存方針を踏襲）
- `npm test`を実装後に必ず通す

## 5. 除外・将来検討

- `components/ui/Input.tsx` / `Textarea.tsx`本体のパディング欠如は、`clubats`含む他18ファイルにも存在するプロジェクト全体の問題。別タスクとして`docs/task-board.md`に記録する
- 種別カラーをユーザーが手動選択できるようにする機能（Notion/Trello方式）は、種別のマスタ管理という別スコープの機能になるため見送り
- カレンダービューへの種別カラー適用は、優先度色分けとの競合のため見送り
