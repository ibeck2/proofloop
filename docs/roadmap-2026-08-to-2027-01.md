## 1. 団体獲得は「新規開拓」ではなく「claim 誘導」である

当初モデルは団体をコールドな新規開拓として計算していた。これは**最大の資産を勘定に入れていなかった**。本番DBを実査した結果（2026-08-07）：

| | 件数 |
| --- | --- |
| 承認済み掲載団体 | 2,421 |
| **うちアカウントの主がいる** | **1件だけ** |
| X アカウント有 | 2,125 |
| Instagram 有 | 1,914 |
| 公式サイト 有 | 1,955 |
| LINE 有 | 17 |
| **いずれかで到達可能** | **2,354（97.2%）** |

やるべきは新規開拓ではなく、**既にページがある団体に「主になってもらう」claim 誘導**である。

### ⚠️ ただし `organizations` にメールアドレス列が無い

到達手段は **SNS DM と公式サイトのフォーム**に限られる。これが2つの帰結を生む。

1. **一斉自動送信ができない。** Resend では送れず、1件あたり2〜3分の手作業になる（1,400件で56時間）。
2. **団体への通知は特定電子メール法の対象外**（メールではないため）。代わりに**各SNSのスパム規約**を守る必要がある。
   - ⚠️ 逆に、**企業打診（430社）は主にメールになるため、そちらが特定電子メール法の対象**。法務確認の対象が団体側から企業側へ移る。

## 2. 🔴 ハードブロッカー：claim 動線が実装されていない

**現状、掲載済みの団体が自分のページを引き取る手段がない。**

`app/(club)/clubdashboard/OrganizationProfileForm.tsx:472-488` を確認した結果、団体を持たないユーザーの唯一の経路は **`organizations` への新規 INSERT** である。既存の掲載レコードに紐づく導線が存在しない。

**このまま1,400団体にDMを送るとどうなるか：**
- 引き取りに来た団体が**重複レコードを新規作成する**
- 元の掲載2,421件は主のいないまま残る
- **重複ページがSEOを毀損する**（せっかく472ページまで伸びたインデックスに duplicate が混ざる）
- claim motion 自体が成立しない

### 実装方針（案）

DMを送る先はその団体の**公式SNSアカウント**なので、「DMを受け取れた＝その団体の管理者である」が成り立つ。**団体ごとに一意のトークン付きURLをDMに載せる**のが最も自然で、追加の本人確認を要しない。

既存の `/invite/[token]` ＋ `organization_invitations` ＋ `accept_organization_invitation` RPC がほぼ同じ形をしている。ただし `organization_invitations.email` が **NOT NULL** で、`invited_by` も既存メンバー前提のため、**そのままでは流用できない**。

⚠️ **スキーマ変更が必要** → CLAUDE.md §5 により Plan Mode での計画提示と承認が必須。

**この実装が終わるまで、掲載通知は1件も送ってはいけない。**

## 3. 100団体は達成できる。ただし回収には効かない

### 達成できる

推奨シナリオ（掲載通知1,400件・claim率8%）で **1月末に累計登録122団体**。到達可能2,354件のうち59%に接触するだけで届く。コストは通知56h＋登録支援24h＋ハンズオン37h＝**117h**、アウトリーチ枠281hの42%に収まる。

claim率が半分の4%に下振れしても61団体、通知を1,650件に増やせば143団体。**目標100団体は現実的なレンジの中にある。**

### ただし6ヶ月の投資回収にはほとんど寄与しない

| | 登録20団体 | 登録122団体 |
| --- | --- | --- |
| 累計成立案件 | 10.3件 | **10.3件（変わらない）** |
| 団体課金（1月） | ¥3,723 | ¥11,713 |
| 累計回収率 | 108.1% | **110.4%（＋2.3ptだけ）** |

**理由：成立案件数の律速は全期間で企業側であり、団体側ではない。** 団体を6倍にしても案件は1件も増えない。増えるのは団体課金だけで、それは月1万円程度にしかならない。

### したがって、100団体の価値は「6ヶ月の外」にある

**この期間の投資回収を根拠に100団体を正当化してはいけない。** 正当化の根拠は別にあり、そちらは正しい。

- **新歓期（3〜4月）の学生流入** — 団体が多いほど学生が来て、団体が新歓・イベント告知に使う（＝ネットワーク効果の本体）
- **B2Cの回遊と検索流入の受け皿**
- **企業への提案力**（マッチング母集団の厚み）
- **将来の課金基盤** — 122団体 × 有料化20% × ¥3,000 ＝ 月¥73,200 のポテンシャル

**⇒ 「6ヶ月の投資回収」と「ネットワーク効果の仕込み」は別々のKPIとして管理する。** 混ぜると、団体数を追って回収を落とすか、回収を追って2月以降の資産を作り損ねる。

### 成立の条件：オンボーディングのセルフサーブ化

1団体3時間のハンズオンを続けると**稼働が115%になって破綻する**。1.5時間（＝自力で登録でき、支援は要点だけ）に落として92.3%。**「100団体を捌ける導線」を作ることが、100団体の前提条件**である。

## 8. リスク

### R-1：協賛単価 ¥500,000 が未検証（最重要）

回収可否のほぼ全てがこの数字に乗っている。¥300,000だと**回収率67.6%**まで落ちる（登録団体数を増やしても回復しない）。
**⇒ 8〜9月の企業打診で最初に確かめる。** 下振れ時は回収の定義をBへ落とすか期間を延ばす判断。**オーナー判断。**

### R-2：claim 動線が未実装（着手順の最上位）

§2 のとおり。**実装前に通知を送ると重複ページでSEOを毀損する。**

### R-3：9月の企業打診60社を、実績がない状態で打つ

9月時点の実運用は9団体。売り物は実績ではなく**2,421団体のデータベースと財務DXの透明性**にせざるを得ない。
**⇒ 8月末までに「実績なしで打てる提案書 v1」を作る。** 無ければ打診が10月にずれ、計画全体が1ヶ月後退して回収に届かない。

### R-4：オンボーディングがセルフサーブ化できない

1団体3時間のままだと稼働115%で破綻する。**100団体は「捌ける導線」とセットでしか成立しない。**

### R-5：歩留まりがすべて仮定

claim率8%・反応率10%・商談化60%・成約率40%はいずれも実測ではない。8月の第1バッチ（200件）が claim率の初回実測を出す。
**⇒ 9月頭に Excel の前提を実測値で更新し、全体を引き直す。**

## 9. 依存関係

```
contact@受信復旧 ─┬─→ Resend認証 ──→ 招待・承認メールが自社ドメインから出る
                 └─→ 営業メールの返信を受けられる

claim動線の実装 ──→ 掲載通知（SNS DM）──→ 登録団体 ──→ セルフサーブ・オンボーディング ──→ 実運用団体
                                                                              ↓
企業ロングリスト ──→ 提案書v1 ──→ 企業打診（9月〜）──→ 商談 ──→ 案件 ──→ 売上（回収の本体）
```

**企業レーンは団体レーンに依存せず並行して走らせる。** これが当初計画との最大の違いであり、回収を成立させる条件。
**団体レーンは回収ではなく、2月以降のネットワーク効果への投資として管理する。**

## 10. 運用ルール

- **毎月末にExcelの実測値を更新する。** 更新するのは前提シートの黄色いセルだけ。
- 実測が仮定と乖離したら、**このファイルの月次目標も書き換える。** 目標を据え置いて未達を積むことはしない。
- 単価 ¥500,000 の検証結果が出た時点で、R-1 の判断をオーナーに上げる。
- **回収レーンとネットワーク効果レーンは、別々に進捗を見る。** 団体数が伸びても回収は進まないし、その逆もある。
